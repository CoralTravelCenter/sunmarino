# Контракт sunmar-tabs

## Назначение и структура

Вкладки для переключения связанных панелей в одной области страницы. Для перехода на другие страницы используйте ссылки.

`sunmar-tabs` управляет непосредственными `sunmar-tab` и `sunmar-tab-content`. Вкладка содержит прямой нативный `<button type="button">`. Панель содержит произвольную разметку. Непустой value связывает пару. Вложенные группы управляют своими вкладками независимо.

## API

| Компонент | Атрибут / свойство | Значение |
| --- | --- | --- |
| sunmar-tabs | `value` | Строковое значение выбранной пары; отражается в атрибуте |
| sunmar-tabs | `aria-label` / `label` | Доступное имя внутреннего tablist |
| sunmar-tab | `value` | Строковый идентификатор; отражается в атрибуте, включая программные изменения |
| sunmar-tab | `forced` | Boolean, задаёт начальный выбор первой доступной forced-вкладки |
| sunmar-tab-content | `value` | Строковый идентификатор; отражается в атрибуте |

`disabled` задаётся на нативной кнопке, не на sunmar-tab. Boolean-атрибуты работают по присутствию. Специальных публичных методов нет.

Пользовательское переключение создаёт `sunmar-tabs-change` с `{ value, previousValue }`, bubbles/composed=true. Константа SUNMAR_TABS_CHANGE_EVENT и тип SunmarTabsChangeDetail экспортируются библиотекой. Перед событием синхронизируются selected, active и ARIA; отражение свойства value самого контейнера завершается в цикле Lit. Программное изменение, нормализация и смена доступности не создают пользовательское событие.

## Выбор и динамическое содержимое

В начальном выборе приоритет имеет первая доступная forced-вкладка, затем запрошенный value, затем первая доступная пара. forced применяется один раз после появления доступных пар, а не при каждом повторном подключении. Во время работы сохраняется доступный value; при его исчезновении выбирается первая доступная пара. Если пар нет, value становится пустой строкой и все панели неактивны.

Значения сравниваются с обрезанными краевыми пробелами. При дублях используется первая вкладка с прямой кнопкой и первая панель для этого value. Disabled первой кнопки не передаёт выбор дубликату. Пары без кнопки, без панели или с пустым value недоступны.

Добавление, удаление, перестановка, замена кнопки, изменения value, disabled, id и slot отслеживаются MutationObserver. Свойства value дочерних компонентов отражаются в DOM, поэтому программные изменения тоже наблюдаются. Синхронизация асинхронная; назначение вкладок и панелей остаётся ответственностью контейнера.

## Владение DOM

Контейнер назначает slots `tab` и `panel`, selected вкладкам, active панелям, ARIA, роли и tabindex кнопкам и панелям. Он сохраняет прежнее значение каждого изменяемого атрибута. При удалении узла или отключении контейнера значение восстанавливается только если оно всё ещё совпадает с последним записанным компонентом. Более позднее отличающееся значение потребителя не удаляется при очистке.

Потребительские непустые ID сохраняются. Сгенерированные ID не используют позицию элемента, поэтому перестановка и добавление не создают повторов. Потребитель отвечает за уникальность собственных ID. Вложенный button не получает копию ID хоста sunmar-tab.

При удалении снимаются обработчики и отключается observer. Повторное подключение заново назначает атрибуты, сохраняя узлы и обработчики потребителя.

## Доступность и клавиатура

Внутренний список имеет role=tablist. Кнопки получают role=tab, aria-selected, aria-disabled, aria-controls и roving tabindex: 0 у выбранной, -1 у остальных. Панели получают role=tabpanel и aria-labelledby, связанный с кнопкой. Панели скрываются стилями sunmar-tab-content при отсутствии active.

Клик выбирает доступную вкладку. Стрелки вправо/вниз выбирают следующую, влево/вверх — предыдущую, с циклическим переходом. Home/End выбирают первую/последнюю. Недоступные вкладки пропускаются, фокус следует за выбором. События из содержимого панели и вложенных групп не переключают внешнюю группу.

## CSS и примеры

Parts контейнера: root, nav, panels. Part панели: content. У sunmar-tab parts нет. Публичная CSS-переменная: `--sunmar-tabs-gap`. Визуальные стили в этом спринте не менялись; оставшиеся фиксированные размеры и media queries требуют отдельной доработки оформления.

Storybook: Default и Dynamic. В Dynamic добавьте второй раздел, затем отключите его: выбор должен вернуться к первому.

Тесты проверяют динамические пары, свойства, disabled, замену кнопок, ID, очистку, повторное подключение, forced, дубликаты, клавиатурные обработчики и события. Happy-dom не заменяет браузерную проверку настоящего Tab-порядка, accessibility tree, видимости панелей и адаптивности.
