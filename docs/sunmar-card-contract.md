# Контракт sunmar-card

## Назначение

Карточка объединяет изображение, заголовок, текст и необязательные действия. Внутренний корень — `article`. Уровень заголовка, описание изображения, ссылки и поведение кнопок задаются потребителем в light DOM.

## CSS-атрибуты

| Атрибут | Поведение |
| --- | --- |
| Без атрибутов | Вертикальная раскладка при ширине окна меньше 1024px; две равные колонки от 1024px |
| `vertical` | Вертикальная раскладка на всех ширинах |
| `reversed` | В горизонтальной раскладке изображение справа, контент слева |

`vertical` приоритетнее `reversed`. Это presence-атрибуты для CSS-селекторов, JS-свойств нет. `vertical="false"` тоже включает вертикальный режим. Для переключения из JS применяется `toggleAttribute`, без реактивных свойств Lit.

Брейкпоинт зависит от окна, а не ширины самой карточки. Узкую карточку на широком экране следует явно помечать `vertical`, если нужна вертикальная раскладка.

## Slots

| Slot | Контракт |
| --- | --- |
| `media` | Обязательный; изображение, обычно `sunmar-image` |
| `title` | Обязательный; заголовок с уровнем, подходящим странице |
| `text` | Обязательный; текст карточки |
| `actions` | Необязательный; отдельные действия либо `sunmar-button-group` |

Обязательность — требование к разметке потребителя, а не runtime-валидация. При отсутствии обязательного слота внутренний контейнер сохраняется. Default slot нет: элементы без имени слота не проецируются.

JS отвечает только за видимость контейнера `actions`: если slot не содержит назначенных элементов, контейнер получает `hidden`. Наличие любого назначенного элемента считается содержимым, даже если это пустая группа. Компонент не проверяет видимость потомков. Содержимое проверяется после первого рендера и при последующих slotchange; каждый раз читается собственный слот actions.

Компонент не клонирует пользовательские элементы, не меняет их семантику и не назначает им обработчики. Собственных публичных методов, событий и интерактивных состояний нет. Нативные действия остаются ответственностью вложенных кнопок и ссылок. Внешних listeners, observers и timers нет.

## Стили

Публичные parts: `root`, `media`, `content`, `title`, `text`, `actions`.

`--sunmar-card-background` задаёт фон контента. Текущие legacy-зависимости сохранены: `--Base-color_Base_Light_Gray`, `--radius-radius_LG`, `--padding-padding_LG`. Их замена требует отдельного согласования и визуальной проверки.

В горизонтальной раскладке карточка задаёт изображению `--sunmar-image-height: 100%`. Внешние размеры и положение карточки определяет потребитель. Раскладку нескольких кнопок рекомендуется задавать через группу.

## Пример

```html
<sunmar-card vertical>
  <sunmar-image slot="media" src="/coast.jpg" alt="Побережье"></sunmar-image>
  <h3 slot="title">Турция</h3>
  <p slot="text">Отдых у моря.</p>
  <sunmar-button-group slot="actions" type="secondary">
    <sunmar-button><a href="/offers">Подробнее</a></sunmar-button>
    <sunmar-button type="primary"><button type="button">Подобрать тур</button></sunmar-button>
  </sunmar-button-group>
</sunmar-card>
```

## Статус проверок

Все шесть тестов happy-dom проходят: проекция слотов, сохранение заголовка и нативных элементов, динамические actions, переназначение slot, повторное подключение и группа кнопок в начальной разметке. Начальная видимость действий синхронизируется явно, без зависимости только от начального slotchange. Для визуальной проверки в Storybook есть `WithButtonGroup`.

Адаптивная раскладка, приоритет CSS-атрибутов и визуальные состояния проверяются пользователем в браузере.
