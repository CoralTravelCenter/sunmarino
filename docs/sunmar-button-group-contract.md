# Контракт sunmar-button-group

Группа отвечает за раскладку и общие настройки непосредственно вложенных `sunmar-button`.

## API

| Атрибут / JS-свойство | Значения | По умолчанию |
| --- | --- | --- |
| `type` | `primary`, `secondary`, `neutral` | `primary` |
| `size` | `small`, `medium`, `large` | `medium` |

Приоритет каждого параметра: явная настройка кнопки → настройка группы → значение по умолчанию. JS-свойства группы возвращают нормализованные значения; присваивание создаёт атрибут. Некорректное явное значение нормализуется в значение по умолчанию. Удаление атрибута группы восстанавливает её значение по умолчанию.

Группа не записывает настройки в атрибуты детей. Изменение группы обновляет оформление кнопок, сохраняя их индивидуальные переопределения. При переносе кнопки настройки пересчитываются. Наследование действует только на непосредственные дочерние `sunmar-button`; вложенные группы и кнопки внутри дополнительных обёрток не наследуют настройки внешней группы.

## Slots, семантика и состояния

Default slot принимает кнопки. Пустая группа не создаёт кнопок или интерактивных элементов. Shadow DOM содержит только slot; автоматического `role="group"` и публичных `part` нет. Собственных методов и событий нет. Клавиатура, фокус, формы и disabled остаются на нативных элементах внутри кнопок. Групповой disabled не предусмотрен.

Нет внешних listeners, observers, timers или ресурсов для очистки. Изменения children обрабатываются через slotchange; повторное подключение кнопки пересчитывает её настройки.

## Адаптивная раскладка

Host: `inline-flex`, `align-items: center`, `flex-wrap: wrap`.

- `--sunmarino-button-group-direction`: `row` (по умолчанию) или `column`.
- `--sunmarino-button-group-gap`: расстояние, по умолчанию `var(--sunmarino-space-s)`.

```css
sunmar-button-group {
  --sunmarino-button-group-direction: column;
}

@media (min-width: 768px) {
  sunmar-button-group {
    --sunmarino-button-group-direction: row;
  }
}
```

Атрибута direction нет. Ширина и внешние отступы задаются потребителем. Внутри SCSS библиотеки адаптивные правила используют общую карту брейкпоинтов.

## Пример

```html
<sunmar-button-group type="secondary" size="large">
  <sunmar-button><button type="button">Общее оформление</button></sunmar-button>
  <sunmar-button type="primary"><button type="button">Главное действие</button></sunmar-button>
  <sunmar-button size="small"><a href="/offers">Предложения</a></sunmar-button>
</sunmar-button-group>
```

Размеры пока отличаются только значениями API: SCSS-секции кнопки пустые и будут заполнены пользователем по макету.

## Проверки

Тесты happy-dom покрывают приоритеты, HTML/JS-изменения, fallback, удаление атрибутов, динамическое добавление, перенос и повторное подключение. Визуальная адаптивная раскладка проверяется пользователем в браузере.
