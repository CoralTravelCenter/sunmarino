# Контракт sunmar-button

Статус: контракт реализован для type, size и наследования от группы; автоматические проверки проходят в happy-dom. Визуальную проверку выполняет пользователь. Размеры по макету пока не заданы.

## Назначение и границы

`sunmar-button` оформляет один нативный элемент действия: `<button>` или `<a href="…">`. Используйте кнопку для действия и ссылку для перехода.

Оболочка не заменяет нативный элемент, не получает `role="button"` или `tabindex`, не перенаправляет фокус и не эмулирует события. Формы, навигация и доступность остаются ответственностью вложенного элемента и потребителя.

## Anatomy и slot

Shadow DOM содержит единственный default slot. В light DOM передаётся один непосредственный дочерний `<button>` или `<a>`. Текст и декоративные иконки располагаются внутри него.

Это требование к разметке потребителя: компонент не проверяет число детей и не исправляет некорректную структуру. Несколько элементов попадут в slot, но такой вариант не входит в поддерживаемый контракт. Обёртка `<div>` между компонентом и кнопкой не поддерживается: `::slotted(button)` не стилизует её потомков.

Пустой slot не создаёт интерактивный элемент. Замена нативного элемента работает через стандартный slot без регистрации дополнительных обработчиков. Компонент не клонирует и не изменяет пользовательский light DOM.

## Attributes и properties

| HTML | JavaScript | Тип | По умолчанию | Поведение |
| --- | --- | --- | --- | --- |
| `type` | `type` | `SunmarButtonType`: `primary`, `secondary`, `neutral` | `primary` | Явный тип кнопки; при отсутствии наследуется от группы |
| `size` | `size` | `SunmarButtonSize`: `small`, `medium`, `large` | `medium` | Явный размер; при отсутствии наследуется от группы. Стили размеров пока пустые |

Приоритет применяется к каждому параметру отдельно: явный атрибут кнопки → атрибут непосредственного родителя `sunmar-button-group` → значение по умолчанию. Обёртки между группой и кнопкой не поддерживаются для наследования. Вложенная группа задаёт собственные настройки.

Отсутствующие атрибуты остаются отсутствующими. Чтение JS-свойств `type` и `size` возвращает итоговые значения. Присваивание свойства задаёт явный нормализованный атрибут; для возврата к наследованию используется `removeAttribute('type')` или `removeAttribute('size')`.

Значения сравниваются точно, без изменения регистра и обрезки пробелов. Некорректное явно заданное значение, включая пустую строку, становится `primary` / `medium` и имеет приоритет над группой. Некорректное JS-присваивание, включая `null` и `undefined`, также задаёт явный fallback; оно не включает наследование.

Внутренние атрибуты `data-resolved-type` и `data-resolved-size` обновляются после цикла Lit и используются стилями. Они не являются настройками для потребителя. Группа не записывает `type` или `size` в дочерние кнопки. При переносе кнопки в другую группу или за пределы группы итоговые настройки пересчитываются при подключении.

`type` на оболочке и `type` на нативной кнопке независимы:

```html
<sunmar-button type="secondary">
  <button type="submit" form="booking">Найти тур</button>
</sunmar-button>
```

На нативном `<button>` задаются `type`, `disabled`, `form`, `name`, `value` и ARIA-атрибуты. На `<a>` — `href`, `target`, `rel` и ARIA-атрибуты. Эти атрибуты не пересылаются с оболочки. Для действия без отправки формы потребитель явно задаёт `type="button"`.

Параметры `variant`, `state`, `loading` и `disabled` не входят в API оболочки. Нативный `disabled` не применяется к ссылке; `aria-disabled="true"` само по себе не блокирует переход.

## Methods и events

Собственных публичных методов и CustomEvent нет. Обработчики действий рекомендуется назначать нативному элементу. Его события распространяются по стандартным правилам DOM и могут обрабатываться делегированием.

Для программного фокуса и клика обращайтесь к вложенному элементу. Компонент не переопределяет унаследованные `focus()` и `click()` для передачи вызова ребёнку.

## Оформление

- SCSS содержит пустые секции `small`, `medium`, `large` по `data-resolved-size`; до заполнения все размеры выглядят одинаково.
- Публичных `part` и индивидуальных CSS-токенов `--sunmar-button-*` сейчас нет.
- Оформление использует глобальные токены `--sunmar-*` для цветов, типографики, отступов и скругления.
- Host имеет `display: inline-flex` и `vertical-align: middle`. Ширина блока, позиционирование и внешние отступы задаются потребителем.
- Несколько действий размещаются через отдельный layout, например `sunmar-button-group`.
- `!important` в правилах slotted-элементов защищает оформление от обычных правил страницы для light DOM. Это ограничивает переопределение этих свойств внешним CSS и является частью текущей интеграции.
- Primary-градиент пока читает legacy-переменные `--Gradient-color_Gradinet_Primary_Second`, `--Gradient-color_Gradient_Primary_First`, `--gradient_Primary_Hover`. Они перечислены как существующая зависимость, а не как рекомендуемый стандарт.

## Состояния и доступность

| Сценарий | Ответственность и поведение |
| --- | --- |
| Начальное состояние | Настройки группы либо `primary` / `medium`, если явные атрибуты не заданы |
| Hover | CSS на устройствах с `hover: hover` и `pointer: fine` |
| Active | Нативный `:active`; для disabled-кнопки специальные active-стили не применяются |
| Focus | Нативный элемент получает фокус; `:focus-visible` задаёт обводку |
| Disabled | Только нативный `<button disabled>`: браузер блокирует действие; CSS меняет прозрачность и курсор |
| Empty / invalid children | Оболочка не генерирует действие, fallback или диагностическое сообщение |
| Invalid type / size | Явные fallback `primary` / `medium` |
| Loading / error | Собственных состояний нет |
| Удаление / повторное подключение | Собственных listeners, observers, timers и внешних ресурсов нет |

Доступное имя задаётся текстом нативного элемента либо его `aria-label`. Декоративные иконки скрываются через `aria-hidden="true"`. Для кнопки работает нативная активация Enter/Space, для ссылки с `href` — Enter. Оболочка клавиатурные события не обрабатывает.

## Примеры

```html
<sunmar-button>
  <button type="button">Подобрать тур</button>
</sunmar-button>

<sunmar-button type="secondary">
  <a href="/offers">Предложения</a>
</sunmar-button>

<sunmar-button type="neutral">
  <button type="button" disabled>Недоступно</button>
</sunmar-button>
```

Storybook уже содержит `Primary`, `Secondary`, `NeutralWithIcon`, `Disabled`, `ExternalForm` в `Components/Button`.

## Проверки

Автоматические тесты проверяют значения по умолчанию, нормализацию HTML/JS, приоритет параметров по отдельности, изменение и удаление настроек, перенос между группами, повторное подключение, замену slot-контента и сохранение нативного элемента, атрибутов и обработчиков.

Визуальная проверка остаётся за пользователем: варианты, hover/active/focus-visible, размеры после заполнения SCSS и влияние стилей сайта. Нативная клавиатура, submit/reset и навигация не подтверждаются тестами happy-dom как полноценной браузерной проверкой.
