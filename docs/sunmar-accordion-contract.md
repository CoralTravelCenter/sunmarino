# Контракт sunmar-accordion и sunmar-accordion-item

## Назначение

Группа раскрываемых секций на нативных `details/summary`. Подходит для вопросов и ответов или дополнительного содержимого. Основную информацию, которую нужно видеть постоянно, лучше размещать вне закрытых секций.

Группа координирует непосредственные дочерние `sunmar-accordion-item`. Каждый пункт можно использовать отдельно. Вложенная группа управляет своими пунктами независимо от внешней.

## API и slots

| Компонент | Атрибут / JS-свойство | Поведение |
| --- | --- | --- |
| Группа | `mode` | `multiple` по умолчанию; `single` допускает не более одного открытого пункта; некорректное значение нормализуется в `multiple` |
| Группа | `faq` | Boolean, по умолчанию false; создаёт соседний script с JSON-LD FAQPage |
| Пункт | `open` | Boolean, по умолчанию false; отражается в атрибуте и нативном details |
| Пункт | `disabled` | Boolean, по умолчанию false; блокирует пользовательское переключение, но допускает программное изменение open |

Boolean-атрибуты работают по присутствию. `open="false"` открывает пункт; для закрытия удалите атрибут или задайте свойство `open = false`.

Группа принимает пункты через default slot. Пункт принимает обязательный непустой заголовок через `header` и содержимое панели через default slot. В заголовке используйте текстовую разметку без вложенных кнопок и ссылок. Обязательность заголовка — требование к разметке потребителя, без runtime-валидации.

Публичных методов и событий нет. `sunmar-accordion-item-toggle-request` — внутреннее событие координации, не API для интеграций. Узлы light DOM не клонируются и не заменяются компонентом.

## Управление состоянием

- В `multiple` можно раскрыть любое количество пунктов.
- В `single` открытие пункта закрывает остальные; разрешено закрыть все пункты.
- При переключении группы в `single`, добавлении пунктов и повторном подключении сохраняется первый открытый пункт в DOM-порядке.
- Программное изменение `open` синхронизируется через цикл обновления Lit. Нативный `toggle` переносит состояние details в свойство; изменение свойства уведомляет группу.
- `disabled` не закрывает уже открытый пункт. Его summary исключается из Tab-порядка и получает aria-disabled.
- Пустая группа не создаёт placeholder. Пустой пункт остаётся disclosure-элементом и требует заполнения заголовка потребителем.
- При отключении группы снимается обработчик координации, отключается MutationObserver и удаляется принадлежащий группе FAQ script. При подключении ресурсы и данные восстанавливаются.

## FAQ

Вопрос объединяет текст непосредственных дочерних элементов пункта с `slot="header"`. Ответ объединяет непосредственные текстовые узлы и текст элементов default slot, включая `slot=""`. Элементы других именованных слотов и комментарии не включаются. Пробельные последовательности сворачиваются, пустые пары исключаются.

Это извлечение textContent соответствующих слотов, без вычисления CSS-видимости вложенных элементов. Потребитель отвечает за содержание ответа.

MutationObserver отслеживает добавление и удаление узлов, изменение текста и атрибута slot. JSON-LD обновляется асинхронно, а не непосредственно в момент изменения DOM. Script расположен рядом с группой; JSON сериализуется с экранированием символа `<`. При отключённом faq или отсутствии полных пар script удаляется.

## Семантика, клавиатура и стили

Раскрытие и доступная семантика принадлежат нативным details/summary. Tab перемещает фокус, Enter и Space переключают доступный пункт. Специальной навигации стрелками нет. Focus-visible имеет видимый контур. Компонент не переопределяет ARIA-атрибуты потребительского light DOM.

У группы parts отсутствуют. У пункта: `root`, `trigger`, `icon`, `panel`, `content`. Внутренние стили используют классы. Используются системные цветовые токены, интервалы, радиусы и тени; отдельных component tokens сейчас нет. Существующие размеры типографики сохранены, их миграция не входит в этот этап.

## Проверки и примеры

Storybook: Multiple, SingleFaq, DynamicFaq, DisabledOpen. В DynamicFaq изменение ответа должно обновить соседний JSON-LD script.

Автотесты проверяют single/multiple, программные изменения, обработку toggle, disabled, вложенность, динамические пункты, повторное подключение и FAQ. Happy-dom не заменяет браузерную проверку: клавиатурную активацию summary, порядок нативных toggle, фокус, раскрытие и внешний вид проверяют в браузере.
